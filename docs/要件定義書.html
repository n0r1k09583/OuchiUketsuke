1. はじめに

1.1 本書の目的

本書は、課題制作の お問い合わせアプリ「おうち受付」の要件を定義する。ホテルや会社の受付の人が使いやすいことを第一とする。誰が・何を・どこまで使うかを文章と図表で示し、設計・実装・評価の共通の基準とする。

1.2 システム概要

お客様は入口の画面から到着やお問い合わせができる。受付担当は予定を管理し、着信に気づき、ビデオまたはチャットで直接応対する。現場にいなくても受付の仕事が続く。

前回課題（React + TypeScript + Vite + Tailwind、Java + Spring Boot + Gradle + PostgreSQL）とは 異なる技術スタック（Next.js、Express、JSON、WebRTC）を使う。AI を補助にしつつ選定と構築は自分で行い、特定技術に依存しない応用力を示す。詳細は技術選定書を参照。

1.3 用語定義

用語定義
施設ホテルまたは会社など、来客を迎える場所。
受付画面入口・フロントのタブレット／PCで開く来客向け画面。

2. 現状分析と導入目的

2.1 想定する現状

ホテルや企業では、来客対応を入口の受付やフロントにいる担当者に頼っている。担当者が不在・在宅勤務・バックヤード作業中だと、来客の到着に気づけず、予定の確認も紙や口頭に散らばりやすい。

2.2 課題

ID課題影響
C-1担当者が現場にいないと、来客の到着が分からない。お待たせ、取りこぼし。
C-2来客予定が分散し、当日の見通しが悪い。案内ミス、担当者不在。
C-3予約外の問い合わせに、その場で担当者と話せない。折り返し待ち。
C-4ホテルと会社で受付の呼び方は違うが、やりたいことは近い。用途ごとに別システムになりやすい。

2.3 導入目的

  1. 自宅にいながら、来客の受付スケジュールを管理できる。
  2. 予定に入っているお客様が来たら、管理者にすぐ分かる。
  3. お客様が問い合わせたいとき、受付担当と直接話せる。
  4. ホテルでも会社でも、施設名を変えて使える。

3. システム化の範囲

3.1 対象範囲

  • 来客予定の登録・照会・更新・削除
  • 受付画面での予約確認（氏名または受付番号）と到着通知
  • 予約なし来訪（お問い合わせ）の受付
  • 管理者への到着・着信の画面表示と音
  • 管理者と来客のビデオ通話・チャット
  • 施設名、種別（ホテル／会社）、あいさつ、管理者暗証番号の設定

3.2 対象外

  • 宿泊予約、部屋割り、決済、社員証による入退館、ゲート開錠
  • メール／SMSでの事前案内、通話の録画保存
  • 本格的な会員登録（メール認証、複数権限のロール管理）

本課題では「予定・到着・会話」に範囲を絞る。基幹システムとの連携は将来課題とする。

5. 業務フロー

5.1 予約来客の到着

① 管理者が来客予定を登録する（氏名・日時・用件・担当者）。受付番号が発行される。 ② 来客が入口の受付画面で「ご予約の方」を選び、氏名または4桁番号を入力する。 ③ システムが当日の予定と照合し、状態を「到着」にする。 ④ 管理者画面に到着通知と音が出る。 ⑤ 来客は待機するか、受付とビデオ通話する。管理者は必要に応じて案内し、対応済にする。

図1　予約来客の到着フロー

5.2 予約なしの問い合わせ

① 来客が「お問い合わせ・直接お話」を選び、氏名を入力する。 ② システムが着信を作り、管理者へ通知する。 ③ 管理者が応答し、ビデオまたはチャットで直接会話する。 ④ いずれかが通話を終了する。

図2　問い合わせフロー

14. 制約・今後の課題

14.1 前提・制約

  • 検証は開発サーバー起動中に行う。入口と自宅が同じURLにアクセスできること。
  • 初版の認証は4桁暗証番号とする。
  • 複雑なネットワークでは映像がつながらない場合がある。そのときはチャットで代替する。

14.2 今後の課題

  • 受付番号のメール／SMS通知
  • 複数管理者、担当者ごとの着信振り分け
  • 来訪履歴の出力、宿泊予約システムとの連携
  • 多言語の受付画面
