# 技術選定書・学習の証明

学校の先生へ。本課題は **お問い合わせアプリ** です。ホテルや会社の受付の人が使いやすいことを第一に考えました。

AI を補助として使いながらも、**技術の選定と構築は自分で判断して進めた**記録です。特定の技術（前回の Vite や Spring）に依存しない応用力を示すための資料です。

## 1. 課題の位置づけ

| 項目 | 内容 |
|------|------|
| 作品名 | おうち受付（お問い合わせアプリ） |
| 利用者 | ホテル・会社の受付担当（自宅からも応対できる） |
| お客様 | 入口の画面から到着や問い合わせができる |
| 公開 | **一般公開していない**（学校提出用） |
| 評価方法 | ローカル起動（フロント 3000 / バック 8080） |

## 2. 前回課題との技術スタックの違い（必須条件）

学校から「前回と **異なる技術スタック** を使うこと」が求められている。

| 層 | 前回の課題（使わない） | 本課題（採用） | 何が違うか |
|----|------------------------|----------------|------------|
| フロントの作り方 | React + TypeScript + **Vite** + Tailwind | **Next.js**（App Router）+ TypeScript | SPA の Vite ではなく、App Router と API 転送（rewrites） |
| バックエンド | **Java + Spring Boot + Gradle** | **Node.js + Express** | JVM / Gradle ではない。同じ言語で API サーバーを自前構築 |
| データベース | **PostgreSQL** | **JSON ファイル** | RDB を使わず、ファイル保存で予定と問い合わせを残す |
| 新しい要素 | （なし／別課題） | **WebRTC**（ビデオ＋チャット） | お問い合わせをその場で直接話す |

前回と同じものに頼らないため、Spring も PostgreSQL も Vite も使っていません。

TypeScript は画面の型付けのために残しています。これは「同じアプリのコピー」ではなく、**別の土台（Next.js / Express）の上で型を使う応用**です。

## 3. なぜこの技術にしたか（自力の選定）

AI に「何を使うか全部決めて」とはせず、条件を自分で置いて選んだ。

1. **受付の人が使いやすい**  
   ブラウザだけで動く。入口は大きなボタン、自宅は一覧と通知。インストール不要。
2. **お問い合わせが途切れない**  
   映像がダメでもチャットが残るように、通話の合図だけサーバー、映像は端末同士（WebRTC）。
3. **前回と重ねない**  
   Vite の代わりに Next.js。Spring/Gradle/PostgreSQL の代わりに Express と JSON。
4. **月額費用を出さない**  
   AWS は無料枠の方針だけ残し、常時サーバーは置かない。評価はローカル。

## 4. AI の使い方と、自分でやったこと

| AI に手伝ってもらったこと | 自分で決めた／確認したこと |
|---------------------------|----------------------------|
| 画面の部品、API の下書き | お問い合わせアプリにする、受付担当が主役 |
| エラーの読み方 | Next.js と Express を分ける |
| 文書の体裁 | 前回スタックを使わない、PostgreSQL を入れない |
| | AWS を作りっぱなしにしない、一般公開しない |
| | 要件定義・技術選定・先生向け資料を提出物にする |

「生成されたコードをそのまま課題にする」ではなく、**要件 → 技術の比較 → 構築 → 動作確認** の順で進めた。

## 5. 作品として先生に見てほしい点

1. 受付画面で「お問い合わせ・直接お話」ができる  
2. 管理者（受付の人）が自宅からスケジュールと着信を見られる  
3. フロント（Next.js :3000）とバック（Express :8080）が分かれている  
4. 前回の Vite / Spring / PostgreSQL 構成ではない  
5. ソースと `docs/` の文書で、選定理由が残っている
